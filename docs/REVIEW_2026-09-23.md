# 2026-09-23 训练启动回归定位与修复

## 现象与环境

`qwen3-musa-validation/scripts/01_train_3iters.sh`（ms-swift Megatron 后端，
Qwen3.5-9B，8×MUSA，PP=4）在 `import swift.megatron` 阶段崩溃，8 个 rank 同样报
`torch.jit.frontend.NotSupportedError: Compiled functions can't take variable number
of arguments`，指向 `transformer_engine/musa/__init__.py:117` 的 `patched_arange`。

- torch 2.7.1 / torch-musa 2.7.1 / torchada 0.1.86（2026-09-15 安装）/
  transformer-engine 2.0.0+651a47b7 / megatron-core 0.16.1 / transformers 5.16.1 /
  ms-swift 4.6.0.dev0（editable）/ training-musa-adaptor 0.1.0.dev0（editable，本仓库）
- 最小复现（设备无关）：
  `TORCH_DEVICE_BACKEND_AUTOLOAD=1 MUSA_VISIBLE_DEVICES=0 python3 -c "import swift.megatron"`

## 根因

1. 本仓库的 CUDA 兼容层（`backends/torch_cuda.py:apply`）按设计 `import torchada`；
   torchada 0.1.86 会把 `torch.arange` 等 factory 包上 device 翻译 wrapper，并为自己
   的 wrapper 注册 TorchScript 别名（`_register_jit_builtin_alias`）。
2. 随后 `import transformer_engine` 触发 `megatron.te.factory-shim.torchscript-compat`。
   MT-TE 的 `patch_after_import_torch()` 执行时 `original_arange = torch.arange`
   捕获到的是 torchada 的 wrapper（不再是 `torch._C._VariableFunctions.arange`），
   再绑定 `torch.arange = patched_arange`，形成两层 shim 链。
3. ms-swift `zigzag_ring_attn.get_half_lse` 的模块级 `@torch.jit.script` 编译时，
   factory-shim 的别名 guard 只接受「直接捕获裸 ATen 函数」的单层形态而拒绝注册
   `aten::arange` 别名 → TorchScript 尝试直接编译 TE 的 `*args, **kwargs` wrapper
   → NotSupportedError。

## 修复

`patches/transformer_engine.py` 的 `_script_factory_aliases` 身份 guard 改为
`_reaches_aten_factory`：沿 plain-function 闭包单元做有界走查（≤32 层包装），
只有字面到达真实 `torch._C._VariableFunctions.<name>` 才注册 `aten::<name>` 别名；
任何其他形态照旧拒绝，不为无关 callable 猜别名。图内语义不变：编译图始终直接解析
ATen 算子（本次修复前后一致），eager 路径的 TE/torchada device 翻译不受影响。
